# 第一次实验：OpenCV 钱币圆检测基线

## 1. 实验目的

本次实验先使用 OpenCV 的 `HoughCircles` 建立钱币定位基线，观察普通背景下的检测效果，为后续自行实现 Canny 和 Hough Circle 算法提供参数和现象对照。

本实验不讨论高纹理背景图片，只分析两个普通背景样本：

- `val/171.jpg`：存在误检；
- `val/261.jpg`：存在漏检。

检测程序为 `src/cv1/opencv_baseline.py`，运行命令如下：

```bash
uv run cv1-opencv-baseline val -o results/opencv
```

## 2. 实验配置

输入图片首先按最长边缩放到 `800` 像素，再进行高斯平滑和
`cv2.HoughCircles` 检测。主要参数为：

| 参数 | 值 | 作用 |
|---|---:|---|
| `dp` | 1.2 | 累加器分辨率相对输入图像的缩放比例 |
| `minDist` | 180 | 检测圆心之间的最小距离（原图坐标） |
| `param1` | 100 | 内部 Canny 的高阈值 |
| `param2` | 50 | 圆心投票检测阈值（第一次基线运行） |
| `minRadius` | 80 | 最小半径（原图坐标） |
| `maxRadius` | 400 | 最大半径（原图坐标） |
| `blurKernel` | 21 | Hough 前高斯平滑核大小 |

检测结果会换算回原始图像坐标，并保存到
`results/opencv/report.json`。坐标原点在左上角，`x` 向右、`y` 向下。

## 3. `171.jpg`：误检分析

原图中可以辨认出约 7 枚钱币。程序输出 9 个圆：

```text
(898.56, 911.36), r=291.84
(627.20, 437.76), r=281.60
(1187.84, 1054.72), r=268.80
(747.52, 686.08), r=250.88
(896.00, 1561.60), r=220.16
(1702.40, 975.36), r=212.48
(1868.80, 345.60), r=209.92
(701.44, 1162.24), r=207.36
(719.36, 865.28), r=128.00
```

其中前 7 个大圆基本对应实际钱币。最后两个圆与左下方的金色钱币及其相邻区域重叠，属于重复/错误候选，而不是新的钱币。因此本图的主要问题不是完全找不到钱币，而是同一目标被多个半径的圆重复解释。

### 原因

1. **钱币内部纹理形成强边缘。** 钱币文字、图案和外圈同时产生梯度。Hough 累加器不只会对外轮廓投票，也可能对内部圆弧或局部弧段投票。
2. **相邻钱币距离较近且发生遮挡。** 左侧金色钱币、菊花钱币和中央钱币相互接近，局部边缘组合可以拼出一个看似合理的圆。
3. **`minDist` 只能约束圆心距离。** 它不能判断两个圆是否覆盖同一个目标，也不能比较两个候选圆的边缘支持率。因此半径不同、圆心略有偏移的重复候选仍会同时保留。
4. **固定半径范围偏宽。** `80~400` 的搜索范围允许局部边缘被解释为较大的背景圆或较小的内部圆，增加了候选数量。

### 改进方向

- 对候选圆计算真实边缘上的圆周支持率，只保留外轮廓支持充分的圆；
- 对高度重叠的候选圆进行 IoU 或圆心距离加半径相似度抑制；
- 对每个候选圆检查内外两侧的灰度变化，排除钱币内部纹理形成的圆；
- 结合连通边缘弧段长度，而不是只使用累加器投票数。

## 4. `261.jpg`：漏检分析

原图中可以辨认出约 7 枚钱币，程序只输出 5 个圆：

```text
(673.28, 352.00), r=98.56
(497.92, 535.04), r=98.56
(770.56, 512.00), r=87.04
(661.76, 659.20), r=80.64
(313.60, 488.96), r=80.64
```

这 5 个结果分别对应右上大钱币、中央银色钱币、右侧金色钱币、下方深色钱币和左侧金色钱币。顶部左侧的小钱币以及顶部中间、被大钱币部分遮挡的深色钱币没有被检测出来。

### 原因

1. **顶部两枚钱币边缘不完整或对比度不足。** 顶部左侧钱币较暗，和浅色背景的边界梯度较弱；顶部中间钱币又部分被右侧大钱币遮挡，完整圆周不存在。
2. **中值滤波和缩放造成弱边缘损失。** 原始 `2048x2048` 图像被缩放到 `800x800`，小钱币的轮廓只剩较少像素；中值滤波进一步削弱了窄的外圈边缘。
3. **`param2=50` 偏保守。** 被遮挡的钱币只能提供部分圆弧，累加票数低于阈值，因此被拒绝。
4. **半径下限和半径量化影响小目标。** 检出的最小半径约为 `80.64`，接近 `minRadius=80`。顶部小钱币的有效外轮廓不足，容易在半径候选筛选时丢失。
5. **遮挡场景不适合要求完整圆周投票。** `HoughCircles` 更擅长检测边缘连续、近似完整的圆；被遮挡目标的可见弧段过短时，投票无法形成稳定峰值。

### 改进方向

- 提高处理分辨率，或只对候选区域使用较大尺寸检测；
- 降低 `param2` 以接受部分圆弧，再通过圆周支持率和灰度边界验证二次筛选；
- 针对小钱币降低 `minRadius`，并按尺寸分组设置检测参数；
- 先提取外轮廓弧段，再允许由多个弧段共同拟合一个圆；
- 对遮挡钱币使用椭圆/圆弧拟合，而不是要求完整圆周。

## 5. 第一次实验结论

在普通背景中，OpenCV 基线能够稳定检测大多数轮廓清晰的钱币，但表现出两个典型问题：

1. **误检：** 内部纹理和相邻目标边缘会形成重复圆候选；
2. **漏检：** 小目标、低对比度目标和被遮挡目标的有效圆弧不足，无法达到投票阈值。

这说明后续自定义算法不能只复现“梯度加圆心投票”，还需要增加候选圆验证和非极大值抑制。对照实验应至少记录检测数量、圆心/半径、圆周边缘支持率，以及不同缩放比例和阈值下的运行时间。

## 6. `101.jpg`、`111.jpg`、`121.jpg`：高噪声背景分析

这三张图片的主体背景都是黑白交错的织物纹理。纹理周期短、对比度高，并且在整幅图像上连续分布，属于典型的高频周期性背景。当前基线结果如下：

| 图片 | 检测圆数量 | 耗时 |
|---|---:|---:|
| `101.jpg` | 103 | 2042.84 ms |
| `111.jpg` | 106 | 1974.00 ms |
| `121.jpg` | 106 | 2124.59 ms |

实际图中只有少量钱币，但检测结果在整张图上布满绿色圆，误检数量远高于真实目标。三个结果的半径还大量集中在约 `396.8`，接近设置的最大半径 `400`，说明累加器在噪声边缘上不断产生大半径候选，最后被半径上限截断。

### 原因

1. **纹理边缘密度远高于钱币外轮廓。** 黑白织物的每个明暗交替都产生梯度，`HoughCircles` 将这些边缘统一作为圆投票来源，背景边缘数量压过了钱币轮廓。
2. **周期性纹理容易拼出伪圆。** 纹理方向和间距具有重复性，许多无关边缘点在某些圆心和半径上偶然累积，形成投票峰值。
3. **`param1` 不能解决结构性噪声。** 内部 Canny 阈值只改变边缘数量，不能区分“钱币边界”和“织物边界”；降低或提高它都可能分别造成漏边或保留大量纹理边缘。
4. **`param2=50` 对高密度边缘过低。** 背景中可用于投票的边缘点很多，即使它们不属于同一真实圆，也容易超过圆心投票阈值。
5. **圆周支持没有做语义验证。** 当前流程只接受 Hough 候选，没有检查圆周边缘是否连续、圆内外灰度是否符合钱币边界，也没有利用钱币外轮廓相对平滑这一特征。
6. **半径范围偏宽且触及上限。** `80~400` 允许背景纹理组合成大量大圆；结果集中出现 `396.8`，表明 `maxRadius` 正在成为候选的人工边界，而不是图像中真实钱币尺寸的自然边界。

### 高噪声问题的解决思路

建议采用“预处理抑制纹理 + 几何候选验证”的组合，而不是单独调高 `param2`：

1. **低通/尺度选择。** 先使用高斯滤波、较大尺度的均值滤波或降采样，压制织物的短周期纹理，再提取钱币尺度的外轮廓。滤波核应通过实验选择，避免把小钱币边缘一起抹掉。
2. **形态学去纹理。** 对二值边缘做开运算、闭运算和小连通域删除，去掉短小、密集、方向重复的纹理边缘，保留较长且近似圆弧的结构。
3. **频域/方向性抑制。** 织物纹理具有明显的周期和方向，可以估计主方向后抑制对应高频响应，或使用带阻滤波去除主频；该方法适合这类固定纹理，但对普通背景的泛化较弱。
4. **限制合理半径。** 根据图像尺寸和已知钱币尺度设置更窄的 `minRadius/maxRadius`，并拒绝贴近半径上下限的候选，防止把搜索边界当成检测结果。
5. **提高候选阈值并分阶段检测。** 先以较高 `param2` 获得高置信候选，再对剩余区域使用较低阈值补检；不能直接全图降低阈值，否则会进一步增加伪圆。
6. **计算圆周支持率。** 在候选圆周上采样，统计附近真实边缘点的比例、最大连续弧段长度和梯度方向一致性。织物伪圆通常只有零散支持，而真实钱币外圈具有更连续的弧段。
7. **检查内外区域差异。** 比较圆周内外一小圈的灰度均值、方差和梯度变化，排除圆内外统计特征与钱币边界不符的候选。
8. **先分割钱币再拟合圆。** 使用颜色/亮度、连通区域或轮廓面积先得到钱币候选区域，再在局部区域做圆拟合，避免全图纹理参与 Hough 投票。
9. **采集更合适的图像。** 从实验条件上减少织物纹理、使用均匀背景或改变照明方向，通常比单纯增加算法复杂度更可靠。

## 7. 将高噪声抑制加入 OpenCV 基线

高斯平滑已经直接加入当前 OpenCV 基线，位于 `HoughCircles` 调用之前，
后续自定义算法只需复刻这一层包装流程，不需要重新设计额外的高噪声检测器。
当前默认 `blurKernel=21`、`param2=25`，其作用是削弱织物的短周期明暗变化，
同时保留钱币尺度的外轮廓。文档前面的 `171/261` 坐标记录属于加入高斯平滑前的
第一次基线运行，保留用于分析原始 OpenCV 包装函数的误检和漏检。

实验调参表明，核大小过小（如 `5` 或 `9`）时，`101/111/121` 仍会产生约
100 个伪圆；核大小为 `21`、`param2=25` 时，三张图片的检测数量分别降到约
`5/5/7`。在当前默认参数重新运行后，三张图片实际分别检测到 `6/5/7` 个候选圆；
相比原始基线的 `103/106/106` 个，误检数量显著下降，但仍需用圆周支持率进一步筛选。
但是过强平滑也会削弱小钱币和遮挡钱币边缘，因此它是抑制噪声与避免漏检之间的折中，
不能单独保证所有场景都正确。

推荐后续在当前基线中继续评估以下兼容措施：

- 将高斯核大小作为可调参数，按图像纹理尺度和硬币尺寸选择；
- 适当缩小图像后再检测，利用降采样平均化高频纹理；
- 对 Hough 候选增加圆周边缘支持率和连续弧段检查；
- 对接近 `maxRadius` 的候选单独降权或拒绝，避免搜索边界制造大圆；
- 必要时先用形态学操作清理短小、密集的背景边缘。
