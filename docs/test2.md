# 第二次实验：自定义 Canny 与 Hough Circle

## 1. 实验目的

在第一次 OpenCV 基线的相同缩放、灰度化、高斯平滑和检测参数下，使用自行编写的
Canny 与 Hough Circle 替代函数，检查两套实现的检测数量和运行时间差异。

自定义实现位于：

- `src/cv1/custom_canny.py`
- `src/cv1/custom_hough.py`
- `src/cv1/custom_pipeline.py`

运行命令：

```bash
uv run cv1-custom val -o results/custom
```

自定义算法没有调用 `cv2.Canny` 或 `cv2.HoughCircles`。OpenCV 只用于图像读写、
缩放、灰度转换和高斯预处理。

## 2. 算法实现

### 自定义 Canny

1. 用 Sobel 算子计算水平、垂直梯度；
2. 计算梯度幅值和方向；
3. 将方向量化为四个方向，并进行非极大值抑制；
4. 用高低阈值区分强边缘和弱边缘；
5. 从强边缘出发连接相邻弱边缘，得到最终边缘图。

### 自定义 Hough Circle

对每个边缘点，根据梯度方向的正、反两个方向估计圆心，并在半径范围内进行投票。
投票峰值按分数排序，再使用圆心最小距离进行非极大值抑制，输出圆心、半径和投票数。

OpenCV 的 `param2` 与自定义累加器的票数定义不同，因此自定义流程使用
`param2 / 4` 作为近似投票阈值。该映射用于保持参数含义接近，不表示两种实现
会产生完全相同的候选圆。

## 3. 当前参数

```text
blur-kernel = 11
min-radius  = 120
max-radius  = 400
param1      = 100
param2      = 32
min-dist    = 180
max-dimension = 800
```

## 4. 初步对照结果

当前普通背景测试集位于 `val/normal/`，共 11 张；`101/111/121/131` 位于
`val/noisy/`，均不参与普通背景统计。重新运行后的普通背景结果如下：

| 实现 | 图片数 | 总检测数 | 平均耗时/张 |
|---|---:|---:|---:|
| OpenCV 基线 | 11 | 59 | 13.0 ms |
| 自定义实现 | 11 | 61 | 189.1 ms |

自定义版本与 OpenCV 的检测数量接近，但圆心和半径不要求逐项完全一致。
高噪声、模糊和倾斜组分别用于观察对应边界因素，不与普通背景平均准确率混合。
单独运行结果为：高噪声组（`--blur-kernel 17`）OpenCV 检测 17 个、自定义检测
20 个。该组包含高噪声背景和轻微倾斜，不与普通背景直接合并。

自定义版本当前明显慢于 OpenCV，主要原因是 Python/NumPy 按半径循环并对边缘点
执行累加；后续可以通过减少边缘点、增加半径步长、局部峰值搜索或使用更紧凑的
累加器优化。

## 5. 验证结论

合成圆测试能够检测出圆心约 `(100, 100)`、半径约 `44` 的圆，说明自定义梯度
方向投票链路可以工作。当前版本已经完成 OpenCV 两个核心包装函数的独立替代，
多尺度融合后，`101.jpg` 从单尺度的 4 个候选提高到 6 个候选；`111.jpg` 和
`121.jpg` 分别为 6 个和 8 个候选。它改善了高噪声组的部分漏识别，但也可能在
其他图片上引入少量候选，因此仍需结合圆周支持率进一步筛选。

## 6. `101.jpg` 与 `131.jpg` 的漏识别分析

自定义算法在 `101.jpg` 和 `131.jpg` 上出现漏识别，主要不是单一超参数造成，
而是图像像素级差异与圆形假设偏差共同作用的结果。

### `101.jpg`：像素级差异

该图包含高频织物背景。缩放到统一的 `800` 像素后，钱币外轮廓的灰度变化、
边缘宽度和梯度方向会受到插值影响。自定义 Canny 使用固定 Sobel 核、四方向量化
和固定高低阈值，得到的有效边缘点数量及位置与 OpenCV Canny 不完全一致。
随后自定义 Hough 只沿梯度正反方向投票，部分边缘点无法在同一圆心和半径上积累到
`param2 / 4` 对应的投票阈值，因此真实钱币候选被漏掉。

此外，织物纹理产生的大量像素级边缘会改变局部梯度方向，使钱币轮廓的投票峰值
不够突出。该问题属于缩放、滤波、梯度计算和投票离散化共同造成的像素级差异。

针对该问题，自定义流程增加了多尺度边缘融合：在主高斯平滑核之外，再使用
`blur_kernel + 4` 的较强平滑尺度提取边缘，将两种尺度的边缘合并，并平均其梯度方向。这样
可以同时保留较清晰的钱币轮廓和较强平滑后的稳定轮廓。默认开启，也可用
`--no-multi-scale` 关闭。

### `131.jpg`：轻微倾斜造成椭圆投影

该图中的部分钱币拍摄角度略有倾斜，圆形在图像平面上的投影更接近椭圆。当前
自定义 Hough Circle 只搜索满足

```text
(x - cx)^2 + (y - cy)^2 = r^2
```

的圆，不能同时拟合长半轴、短半轴和旋转角度。当椭圆边缘在不同方向到圆心的
距离不一致时，同一个候选无法在单一半径上形成足够投票，最终被判定为非圆或漏检。

因此，`131.jpg` 的漏识别与高噪声背景下的轻微倾斜有关；
这里的轻微倾斜已经足以让部分圆轮廓偏离固定半径模型。

### 结论

- `101.jpg` 的主要原因：缩放、纹理和梯度计算带来的像素级边缘差异；
- `131.jpg` 的主要原因：轻微倾斜使圆形投影呈椭圆，超出圆 Hough 模型；
- 两者都不能仅靠提高或降低 `param2` 完全解决。

如果扩展实验范围，可以分别采用多尺度边缘融合、局部自适应阈值，以及椭圆
Hough/椭圆拟合。但在当前任务中保留圆检测模型和既定边界约束，不对这两类情况
额外修正。

## 7. 普通组参数对照记录

在普通背景组的对照试验中，OpenCV 与自定义实现的边缘表现存在明显差异：

- **OpenCV 方案**：使用高斯核 `9`、`param2=50` 时，边缘提取更连续、圆滑，
  基本能够完整提取钱币圆轮廓，最终圆检测结果较稳定；
- **自定义方案**：在相同参数下无法得到同等完整的圆形边缘。由于自定义
  Canny 的梯度计算、非极大值抑制和滞后连接与 OpenCV 的内部实现不同，
  直接复制 OpenCV 参数不能保证相同的边缘响应；
- **当前折中方案**：自定义算法使用高斯核 `11`、`param2=40`，虽然边缘图仍
  不够完整，但 Hough 投票和候选抑制后能够获得近似的有效识别率。

这说明当前两种实现的参数不能简单按数值一一对应。OpenCV 参数更适合作为基线
记录；自定义算法需要依据自身边缘数量、边缘连续性和 Hough 投票尺度单独校准。
比较时应同时记录边缘图质量和最终有效识别结果，不能只比较 Canny 边缘像素数量。

## 8. 投票机制改进

当边缘图看起来接近、但自定义 Hough 仍无法识别时，主要原因是投票过于离散：
每个边缘点被四舍五入到单个整数圆心，圆弧上的像素误差会把本应属于同一圆的票
分散到相邻累加器位置。

为此，自定义 Hough 增加了圆心累加器降采样。该机制可通过 `--dp` 开启；当前默认
`dp=1.0` 保持原始结果，实验参数可设为 `dp=1.1`。启用时先将相邻圆心
映射到较小的累加器，再把峰值坐标映射回原图。它不是增加背景平滑，而是合并
像素级相近的投票，使不完整圆弧更容易形成稳定峰值；圆心最小距离抑制仍在原图
坐标中执行。

初步测试表明，`dp=1.1` 能改善部分偏移圆弧的投票峰，但也会增加候选：当前普通
组自定义检测由 61 个增至 70 个，高噪声组由 22 个保持为 22 个。因此暂不将它
作为默认修正，只保留为可控实验参数。`dp` 过大则会把相邻伪圆也合并，应保持在
`1.0~1.2` 附近，并继续结合圆周支持率筛选。
